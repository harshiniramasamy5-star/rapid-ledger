## Architecture

RAPID Ledger uses a central `WebhookDispatcher` singleton. All integrations subscribe as handlers — no integration-specific code lives inside document services.

```
Document service
  → webhookDispatcher.dispatch("document.approved", payload)
    → NotionSyncService.handle()   ✅
    → LinearWebhookHandler.handle() (if LINEAR_API_KEY set)
    → [your custom handler]
```

## Supported Events

| Event | Trigger |
|-------|---------|
| `document.approved` | Document reaches approved status |
| `document.rejected` | Document rejected by approver |
| `document.published` | Document finalized |
| `transcript.created` | Transcript document created |
| `transcript.updated` | Transcript content updated |

## Payload Shape

```typescript
{
  documentId: string;
  userId: string;
  timestamp: string;  // ISO 8601
  data?: Record<string, unknown>;
}
```

## Failure Handling

- All handlers run via `Promise.allSettled` — one failure never blocks others
- Failed handlers are logged to AuditLog as `webhook_failed`
- Use the resync endpoint to retry Notion failures

## Manual Linear Trigger

If `LINEAR_API_KEY` and `LINEAR_TEAM_ID` are set:

```bash
curl -X POST https://rapid-ledger-production.up.railway.app/api/webhooks/linear/trigger/<docId> \
  -H "Authorization: Bearer <admin_token>"
```

Creates a Linear issue from the approved document.

## Audit Events

| Event | Trigger |
|-------|---------|
| `webhook_failed` | Any handler throws |
| `webhook_retried` | Manual resync triggered |
| `notion_synced` | Notion sync succeeds |
| `sync_failed` | Notion sync fails |
