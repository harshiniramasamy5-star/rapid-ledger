The Approvals API gives users assigned to the **A** (Agree) role a consolidated view of every document currently awaiting their formal sign-off. This queue surfaces documents in `awaiting_agreement` status where you hold the **A** role — meaning high-risk and critical-risk decisions that require agreement before an Admin can finalize them. Use this endpoint to build dashboards, notification systems, or automated workflow triggers based on pending actions.

---

## Get Your Pending Approvals

Returns all approval records assigned to the authenticated user where the document is in `awaiting_agreement` status and the user holds the **A** (Agree) role. Each item includes a summary of the associated decision document so you can assess and prioritize without making additional requests.

**GET** `/api/approvals/my`

```bash
curl "https://rapid-ledger-production.up.railway.app/api/approvals/my" \
  -H "Authorization: Bearer $TOKEN"
```

**Response — 200 OK**

```json
[
  {
    "id": "clxapprv000010",
    "status": "pending",
    "document": {
      "id": "clx4k2mn0000008l5hgqf9z3c",
      "documentCode": "RAPID-003",
      "title": "Decommission legacy payment processor",
      "riskLevel": "critical",
      "complianceImpact": true,
      "decisionSummary": "Retire the legacy Stripe integration in favour of the new provider."
    }
  },
  {
    "id": "clxapprv000011",
    "status": "pending",
    "document": {
      "id": "clx4k2mn0000008l5hgqf8y2b",
      "documentCode": "RAPID-007",
      "title": "Expand data retention policy to 7 years",
      "riskLevel": "high",
      "complianceImpact": true,
      "decisionSummary": "Extend the default data retention period to meet updated GDPR guidance."
    }
  }
]
```

<ResponseField name="id" type="string">
  The unique ID of the approval record.
</ResponseField>

<ResponseField name="status" type="string">
  The current approval status. All items returned by this endpoint have a `pending` status.
</ResponseField>

<ResponseField name="document.id" type="string">
  The unique ID of the associated decision document.
</ResponseField>

<ResponseField name="document.documentCode" type="string">
  The human-readable document code (e.g. `RAPID-003`).
</ResponseField>

<ResponseField name="document.title" type="string">
  The title of the decision document.
</ResponseField>

<ResponseField name="document.riskLevel" type="string">
  Risk classification: `low`, `medium`, `high`, or `critical`.
</ResponseField>

<ResponseField name="document.complianceImpact" type="boolean">
  Whether the document has a regulatory or compliance implication.
</ResponseField>

<ResponseField name="document.decisionSummary" type="string">
  A concise summary of the decision being approved.
</ResponseField>

<Note>
  Only users with the **A** (Agree) role assigned on one or more documents will receive results from this endpoint. Documents that are not in `awaiting_agreement` status — or where you are not assigned the **A** role — will not appear.
</Note>

## Acting on Approvals

There is no separate approvals action endpoint. Once you have reviewed a document, use the [Documents API](/api-reference/documents) to record your decision. Reference the `document.id` from the approval queue response above.

### Approve a Document

Formally agree to the decision. The document transitions to `approved`, and the Admin holding the **D** (Decide) role can subsequently finalize it.

**POST** `/api/documents/:id/approve`

```bash
curl -X POST "https://rapid-ledger-production.up.railway.app/api/documents/clx4k2mn0000008l5hgqf9z3c/approve" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "notes": "Reviewed and approved. Compliance risk has been fully addressed." }'
```

**Response — 200 OK**

```json
{
  "id": "clx4k2mn0000008l5hgqf9z3c",
  "status": "approved",
  "updatedAt": "2024-06-12T11:00:00.000Z"
}
```

---

### Reject a Document

Reject the document and return it to the creator with a written reason. The document transitions to `rejected`.

**POST** `/api/documents/:id/reject`

```bash
curl -X POST "https://rapid-ledger-production.up.railway.app/api/documents/clx4k2mn0000008l5hgqf9z3c/reject" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "notes": "Missing compliance evidence. Please attach the latest security audit before resubmitting." }'
```

**Response — 200 OK**

```json
{
  "id": "clx4k2mn0000008l5hgqf9z3c",
  "status": "rejected",
  "updatedAt": "2024-06-12T13:30:00.000Z"
}
```

### Provide a Recommendation

Users assigned to the **R** (Recommend) role use this endpoint to provide their formal recommendation before the document moves to the agreement stage. This is also a Documents API endpoint — the recommendation queue is managed through `GET /api/approvals/my` only for **A** role holders.

**POST** `/api/documents/:id/recommend`

```bash
curl -X POST "https://rapid-ledger-production.up.railway.app/api/documents/clx4k2mn0000008l5hgqf9z3c/recommend" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "notes": "I recommend proceeding. The proposed approach has been validated against our compliance framework." }'
```

**Response — 200 OK**

```json
{
  "id": "clx4k2mn0000008l5hgqf9z3c",
  "status": "awaiting_agreement",
  "updatedAt": "2024-06-11T10:00:00.000Z"
}
```

---

<Note>
  Only users with the **A** (Agree) role assigned on the document can approve or reject it. If you attempt to approve a document without the **A** role assignment, you will receive a **403 Forbidden** response.
</Note>

<Tip>
  Poll `GET /api/approvals/my` on a schedule or after receiving an in-app notification to keep your approval queue up to date. Documents you have approved or rejected will no longer appear in subsequent responses.
</Tip>
