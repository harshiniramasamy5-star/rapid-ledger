The Transcripts API processes meeting transcripts using an AI model to automatically extract decisions and assign RAPID roles. Rather than manually creating a document after every meeting, you submit the raw transcript and the pipeline produces a structured draft document with role assignments pre-populated. Only transcript sections tagged with the `[RAPID]` prefix are used for extraction — everything else is ignored.

---

## Submit a Transcript

Submit a meeting transcript for AI processing. The pipeline parses `[RAPID]`-tagged sections, identifies the decision being made, infers RAPID role assignments from participant names mentioned in those sections, and creates a new document of type `TRANSCRIPT` in `draft` status.

**POST** `/api/transcripts`

<ParamField body="transcript" type="string" required>
  The full meeting transcript text. The AI extraction engine only processes sections prefixed with `[RAPID]`, so you can include the complete raw transcript.
</ParamField>

<ParamField body="parentDocumentId" type="string">
  Optional. The ID of an existing RAPID document to link this transcript to. Use this when the meeting was a follow-up discussion on an in-progress decision.
</ParamField>

```bash
curl -X POST "https://rapid-ledger-production.up.railway.app/api/transcripts" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "transcript": "Alice: Lets get started. We have a packed agenda today.\n\n[RAPID] Alice: We need to make a final call on the database migration. I am deciding we move to PostgreSQL 16 on the September maintenance window.\n\n[RAPID] Bob: I recommend we proceed — the compliance risk of staying on PG14 is too high. I have attached the security audit to the internal wiki.\n\n[RAPID] Carol: I agree, provided the blue-green deployment strategy is followed to minimise downtime.\n\n[RAPID] Dave: I will perform the migration. I can have the runbook ready two weeks before the window.\n\nAlice: Great. Lets move to the next item.",
    "parentDocumentId": "clx4k2mn0000008l5hgqf1a2b"
  }'
```

<ResponseField name="document.id" type="string">
  The ID of the newly created draft document.
</ResponseField>

<ResponseField name="document.documentCode" type="string">
  The auto-generated document code for the transcript-derived document (e.g. `RAPID-T-001`).
</ResponseField>

<ResponseField name="document.title" type="string">
  The document title generated by the AI from the meeting content.

  Always `TRANSCRIPT` for documents created via this endpoint.

</ResponseField>

  The ID of the audit log entry recording this transcript submission.
</ResponseField>

## Fathom Webhook

RAPID Ledger supports automated transcript ingestion from Fathom Video via a webhook endpoint. When configured, Fathom will POST the transcript to RAPID Ledger immediately after a meeting ends, removing the need for manual submission entirely.

**POST** `/api/webhooks/fathom`

**Signature validation:** Every request from Fathom includes an `X-Fathom-Signature` header containing an HMAC-SHA256 signature of the raw request body. RAPID Ledger validates this signature before processing. Requests with an invalid or missing signature are rejected with a **401 Unauthorized** response.

```
X-Fathom-Signature: sha256=3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c
```

**Idempotency:** Each Fathom webhook event includes a unique `callId`. If RAPID Ledger receives a duplicate `callId` — for example due to a retry — the duplicate is silently ignored and a `200 OK` is returned. This prevents duplicate documents from being created.

**Example webhook payload shape:**

```json
{
  "callId": "fathom-call-abc123",
  "meetingTitle": "Q3 Infrastructure Planning",
  "startedAt": "2024-06-12T14:00:00.000Z",
  "endedAt": "2024-06-12T15:00:00.000Z",
  "transcript": "[RAPID] Alice: We are deciding to migrate to PostgreSQL 16 in September. I am making this call.\n\n[RAPID] Bob: I recommend this approach. Risk assessment is complete.\n\nAlice: Any other business?"
}
```

<Note>
  Contact your organisation Admin to obtain the webhook secret. You will need it when configuring the RAPID Ledger webhook in your Fathom Video settings. The secret is used to generate and verify the HMAC-SHA256 signature that RAPID Ledger validates on every inbound request.
</Note>

## Tagging Conventions

The AI extraction engine processes only the parts of a transcript that are prefixed with `[RAPID]`. This lets you include full meeting transcripts without irrelevant portions affecting the extracted decision.

**Rules:**
- Tag each line or paragraph that contains decision-relevant content with `[RAPID]` at the start.
- Each tagged line should include the speaker's name so the AI can infer role assignments.
- Use natural language — the model understands phrases like "I'm deciding", "I recommend", "I'll perform", "I agree", and "I can provide input".

**Example:**

```text
Alice: Let us kick off with the quarterly review numbers.
Dave: Revenue is up 12% quarter-on-quarter.

[RAPID] Alice: I am deciding we will sunset the legacy billing service by end of Q3.
[RAPID] Bob: I recommend this based on the cost analysis I shared last week.
[RAPID] Carol: I agree, provided we have a rollback plan documented.
[RAPID] Dave: I will perform the migration. I will own the rollback runbook.

Alice: Great. Moving on to hiring...
```

Only the four `[RAPID]`-tagged lines are sent to the extraction model. The rest of the transcript is discarded before processing.

<Tip>
  Link a transcript to an existing RAPID document by passing `parentDocumentId` in your request. This preserves the full decision chain — for example, linking a follow-up implementation meeting back to the original approval document.
</Tip>
